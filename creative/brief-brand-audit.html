Known Issues to Investigate

These are documented problems. Your audit should confirm each, rate severity, and propose resolution.

1 · Two accent colours doing the same job

#FF7A23 (logo orange) — used in ads, print, all SVG creative.
#9F4D2D (terracotta) — used on website for links, CTAs, buttons.

These are visually distinct and have never been reconciled. Someone landing from an ad sees orange; on the website they see terracotta. Not a two-tone system — an unresolved collision.

Question to answer: Should they merge into one accent, or be formalised as distinct contexts (print vs web)? If merged, which wins?

2 · Costa font on website ✅ resolved

Costa Light is now the Latin display font on the website. Saged Cyrillic handles Cyrillic headings. Summer Font and Cormorant Garamond have been removed from all files.

3 · Logo on dark backgrounds uses CSS invert

The website applies filter: invert(1) to produce a white version of the logo. This is a workaround — not a real white-on-dark asset. A proper white PNG exists at creative/library/01-brand/logos/logo-white.png.

Question to answer: Is the current approach acceptable, or does the site need a properly rendered dark-mode logo implementation?

4 · No brand guidelines document

Rules exist scattered across DESIGNER.md, SAGED-SOURCE-OF-TRUTH.md, and CLAUDE.md. There is no single designed brand guide a human freelancer can open and trust.

Deliverable needed: A one-page brand reference — colour values, font names, logo rules, do/don't examples. PDF or HTML.

5 · Photo categorization error

creative/library/03-photos/koritsia/koritsa-editorial.jpg is a fashion editorial photo — labeled as an instructor photo. It was accidentally used in early ad creative. Needs to be quarantined or relabeled so it's not used in ceramics ads.

6 · No RU/UA adult ceramics ad in reproducible format

The original Koritsia ceramics ad exists only as an .ai source file — not easily editable or variant-able. English ad has an SVG workflow (v1–v4). Russian equivalent doesn't.

Flag this if you see it blocking campaign consistency.

Constraints

Do not propose solutions that break these.

Technical

HardWebsite is vanilla HTML/CSS/JS — no React, no Tailwind, no build step. Changes must be plain CSS/HTML.
HardHosted on GitHub Pages — no server-side rendering, no backend.
HardFont files must be self-hosted or Google Fonts. No Adobe Fonts/Typekit (GDPR consent complexity).
HardGDPR consent banner must fire before Meta Pixel tracking. Do not touch or propose removing consent logic in script.js.
HardRU landing (index.html) and UA landing (uk/index.html) must stay structurally identical — any layout change on one must be mirrored in the other.

Creative

HardBrand personality stays: warm, handmade, playful, honest. Not minimalist-cold, not corporate, not tourist-brochure.
HardCream background (#F9F4ED) is load-bearing — it IS the warmth. Do not replace with white.
HardCosta font is non-negotiable for print/ad creative. If it comes onto the website, it comes at full weight — not as a supplementary accent.
HardBrand figures (illustrated characters) stay — they are the texture of the brand.
NoteThis is not a rebrand. It's a brand audit. Propose refinements, not replacement.

Business

NoteOwner is one person with no design budget for a full system rebuild. Prioritise high-impact, low-effort fixes.
NoteThe best-performing ad on record used English-language video + "Saged.club is for..." positioning. Proposals should be compatible with that creative direction.
NoteEvents are promoted organically only — never via paid ads. Event-specific design changes don't need to be optimized for ad performance.

What Good Looks Like

Deliverable 1

Audit report

Each of the 6 known issues assessed with a severity rating (critical / notable / minor) and a concrete recommendation. New issues you find that aren't listed above are welcome — add them.

Deliverable 2

Proposed changes document

Specific, implementable changes. Not "improve type hierarchy" — instead "Costa Light at 72px, letter-spacing −0.04em, colour #2A2520." Enough detail that a developer or Claude Code session can implement each change without further design input.

Deliverable 3

One-page brand reference

A designed PDF or HTML file: colour swatches with hex values, font names and weights, logo rules, do/don't examples. Something Diana can send to a new collaborator without needing to explain anything verbally.

Deliverable 4

Priority order

Which changes should Diana do first? Ordered by: user-facing impact × implementation effort. The top 3 should be doable in a single working session.
